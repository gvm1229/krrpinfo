> 2026-10-22 · feat/cms-mvp · 사용자 요청에 따른 점검, 제품 코드 수정·재배포 제외

## 기준과 범위

- 사용자 기준: 직접 작성한 조작 UI는 shadcn 구성요소 사용. shadcn 내부의 의미 있는 HTML과 Slate·CodeMirror 내부 편집 요소는 직접 작성한 대체 UI와 구분
- 사용자 후속 명확화: Strapi에서 가져온 원본 UI는 shadcn 전환 대상에서 제외. 아래 집계는 일괄 교체 지시가 아니며 변경 전 출처와 이식 기록으로 자체 작성 부분만 선별
- 디자인의 정본은 사용자가 만든 기존 krrpinfo 화면. DESIGN.md도 기존 구현과 대조하며 새로 추가한 관리자 전용 기준을 원본 디자인으로 오인하지 않음
- 조작 요소는 app과 src/components의 실제 화면 코드를 제한 조회. shadcn 기본 구현·보존한 외부 소스·공개 본문 안의 콘텐츠는 별도 분류
- 관리자 점검은 레이아웃·로그인·목록·편집기·미디어·설정과 연결된 스타일에 한정

## 순서와 완료 기준

1. 직접 작성한 HTML 조작 요소·브라우저 기본 확인창·사용 중인 shadcn 구성요소 목록 확인 → 정확한 파일·줄·개수와 예외 근거
2. DESIGN.md의 최초 커밋과 이전 화면·색상·버튼·글꼴·테마 비교 → 원본에서 온 기준과 CMS 구현 때 추가한 기준 구분
3. 실제 관리자 화면과 가능한 키보드·반응형 상태 확인 → 코드 증거와 실제 화면 증거, 미실행 범위 구분
4. 반복되는 위반을 영향과 수정 우선순위로 정리 → 이 문서에 결과·수정 대응표·증거 한계 기록

## 실제 화면 확인과 한계

- 실행: Codex·Windows·Chrome, 로그인된 기존 Preview의 대시보드·글 목록·비어 있는 새 글 폼·미디어 창을 읽기 전용으로 확인했다. 저장·삭제·업로드·상태 전환은 실행하지 않았다.
- 어두운 테마: 배경 rgb(24,24,38), 패널 rgb(33,33,52), 버튼 모서리 4px로 별도 관리자 디자인 적용 확인. 미디어 창 열기 시 닫기에 초점 이동, Escape로 닫힘은 정상이다.
- 390×844px 화면 크기 모의 검사: main 약 374.67px·폼 약 334.67px, 문서 scrollWidth 375px로 폼 전체 가로 넘침 없음. 좌측 메뉴는 위로 이동하고 메뉴 내부는 별도 가로 스크롤이다. 실제 휴대전화·터치 제스처를 검증한 결과는 아니다. 창 크기 임시 설정은 복원했다.
- 아이콘의 lucide-react 사용·Pretendard·입력 이름·오류 메시지 영역·진행 중 버튼 비활성화·기본 버튼의 nowrap과 shrink 방지는 유지할 부분이다. 로그인·사이트 설정은 코드로 확인했으며 이번에 따로 로그인하거나 저장하지 않았다.
- 밝은 테마는 CSS만 확인했다. 실제 밝은 화면·키보드 전체 이동·스크린 리더·명암 대비 전체 측정·성능/부하 시험은 이번 점검에서 실행하지 않았으므로 통과로 판단하지 않는다.
- Impeccable 탐지기는 지정한 관리자 소스와 admin.css에서 빈 목록 []을 반환했다. 이 탐지기가 프로젝트의 shadcn·원본 디자인 규칙을 입증하는 것은 아니며 위 구문 트리·코드·실제 화면 결과를 대체하지 않는다.
- 제품 코드 변경이 없어 테스트·빌드·배포는 반복하지 않았다. 문서와 검사 보조 자료만 생성했고 버전은 0.1.25로 유지한다.

## 후속 수정 대응표 — 이번 점검에서 미실행

1. 원본 디자인과 최신 사용자 규칙으로 DESIGN.md 정정. 자체 작성 UI와 가져온 Strapi 원본의 출처·적용 범위 구분, Strapi 원본 UI 보존
2. 자체 작성한 공통 입력·체크·선택·버튼과 버튼형 링크만 교체. 없는 Textarea·AlertDialog 등은 기존 shadcn 구현 방식에 맞춰 추가
3. 자체 작성한 미디어 창·삭제/형식 변경 확인창과 도구막대만 교체. 날짜·색상 선택도 Popover/Calendar와 색상 선택 메뉴로 검토
4. Slate의 실제 편집 영역·CodeMirror 내부 입력·파일 선택기의 내부 input은 기술적으로 필요한 HTML과 구분. CodeMirror 연결 textarea까지 단순 일반 입력으로 치환해 편집 기능을 깨뜨리지 않으며 shadcn 경계·ref 보존 방식으로 처리
5. 자체 작성한 관리자 팔레트·styled-components 경로에 한해 정리, 초점·조작 영역·공개 화면 후보 반영. Strapi 원본 UI와 기존 콘텐츠·저장·선택 범위·한글 입력 기능 보존
6. 관련 저장/편집 회귀 검사·타입·빌드와 두 테마·모바일 화면 재확인. Impeccable의 harden → adapt → polish 순서로 마감 후 audit 재검사
