# Strapi를 우선 재사용하는 1인용 CMS MVP — 수정 계획

> 보존일: 2026-10-21
> 상태: feat/cms-mvp에서 단계별 커밋·로컬 검증 완료, 실제 R2 전송 확인, DB 초기화·브라우저 업로드·Preview 검증 대기

## 1. 사실 확인과 기술 선택

**Strapi는 기본 편집기에 Tiptap을 사용하지 않는다.** 2026-10-21에 확인한 최신 정식판 **5.58.0** 기준이다.

| Strapi 기능        | 확인한 기술                                                                                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Markdown 입력      | [CodeMirror 5](https://github.com/strapi/strapi/blob/v5.58.0/packages/core/content-manager/admin/src/pages/EditView/components/FormInputs/Wysiwyg/Editor.tsx)                              |
| Markdown 미리보기  | [markdown-it](https://github.com/strapi/strapi/blob/v5.58.0/packages/core/content-manager/admin/src/pages/EditView/components/FormInputs/Wysiwyg/utils/mdRenderer.ts)                      |
| Blocks 시각 편집기 | [Slate·Slate React·Slate History](https://github.com/strapi/strapi/blob/v5.58.0/packages/core/content-manager/admin/src/pages/EditView/components/FormInputs/BlocksInput/BlocksEditor.tsx) |

공식 문서와 해당 버전의 소스·패키지 정보를 대조했다. Strapi 실행 환경에서 직접 시험한 결과는 아니다.

이전 Tiptap 제안은 철회한다. **Strapi의 실제 기술·소스·화면 동작을 우선 사용하고, 현재 환경과 충돌하는 부분만 조정한다.**

- Next.js·React 19·Server Actions·Vercel 단일 배포를 유지한다.
- Strapi 서버와 유료 기능은 도입하지 않는다.
- Community 소스에서 필요한 편집·목록·미디어 UI를 선별하고 출처·버전·라이선스를 보존한다.
- Strapi UI 패키지 2.2.4의 공식 React 지원 범위는 18이다. 전체 패키지 강제 설치나 React 하향 대신 필요한 UI 소스를 React 19에 맞춰 이식한다. 이는 실제 실행 실패가 확인됐다는 뜻은 아니다.
- Strapi의 관리자 문맥·인증·API 호출은 NextAuth 기반 자체 로그인과 Server Actions에 연결하는 작은 연결부로 대체한다.
- 새 관리자 UI는 Strapi 구성과 스타일을 기준으로 한다. 다른 관리 도구나 편집기로 바꾸는 것은 검증된 장애가 있을 때만 다시 검토한다.

## 2. 관리자 기능과 고정 데이터 제거

운영자는 한 명이다. Google 로그인을 제거하고 NextAuth 기반 자체 로그인으로 교체한다. 새 콘텐츠는 Draft로 시작하고 Published 콘텐츠는 **저장 후 다음 조회부터 즉시 반영**한다.

관리 범위는 다음과 같이 확대한다.

| 영역           | 관리자에서 변경할 내용                                                 |
| -------------- | ---------------------------------------------------------------------- |
| 글             | 본문·제목·설명·태그·날짜·썸네일·공개 상태                              |
| 추천 영상      | YouTube URL·제목·채널명·썸네일·분류·순서·노출                          |
| 시즌·일정      | 서버 구분·시즌 정보·날짜·배너·타임라인·홈 카운트다운                   |
| 쿠폰           | 코드·설명·만료일·노출                                                  |
| 홈             | 소개 문구·대표 이미지·연결 대상·추천 항목·유용한 링크·섹션 순서와 노출 |
| 메뉴·푸터      | 이름·링크·순서·하위 메뉴·연락처·저작권 표시·QR 이미지                  |
| 사이트 정보    | 사이트 이름·설명·로고·공유 이미지·검색 메타데이터·작성자 정보          |
| 공개 화면 문구 | 페이지 제목·안내·버튼 문구·검색 및 빈 목록 문구                        |
| 분류·표시 설정 | 영상 분류·태그·표시 이름·콘텐츠 영역의 활성 여부                       |

**콘텐츠와 운영 설정을 바꾸기 위해 코드를 수정하거나 다시 배포할 필요가 없도록 한다.** 데스크톱 메뉴·모바일 메뉴·검색·사이트맵은 같은 저장 데이터를 사용한다.

- 디자인 값은 현재 화면을 기준으로 코드와 `DESIGN.md`에서 관리한다. 콘텐츠에는 허용된 디자인 이름을 선택하는 기능만 제공한다.
- 라우트 구현, 검증 규칙, 보안 정책은 코드에 둔다. 비밀키·인증 계정·서비스 연결 정보는 환경 설정에 둔다.
- 홈은 기존 섹션의 내용·순서·노출을 편집한다. 임의 코드를 실행하는 페이지 제작기는 만들지 않는다.
- 초기값은 일회성 데이터 입력에만 사용한다. 삭제하거나 비운 항목을 코드의 기본값으로 되살리지 않는다.
- **배경음악은 제거한다.** 플레이어·연결 코드·다른 사용처가 없는 전용 음원을 정리하고 CMS나 R2로 이전하지 않는다.

관리 화면에는 콘텐츠 목록·검색·필터·추가·편집·삭제, 미디어 선택, 사이트 설정을 제공한다. 회원 관리·협업·승인 절차·변경 이력 기능은 MVP에 추가하지 않는다.

## 3. 편집기·데이터·파일 연결

**편집기**

- 새 글의 기본 편집기는 Strapi의 Slate 기반 Blocks 편집기를 선별 이식한다. 도구 모음·블록 변경·목록·링크·이미지·실행 취소 등의 동작을 우선 보존한다.
- Strapi 기본 블록에는 표·YouTube 삽입·접기가 없다. 이미 선택한 기능을 제공하기 위해 같은 Slate 구조에 해당 블록과 필요한 서식만 확장한다. 이를 Strapi 기본 기능으로 설명하지 않는다. [기본 블록 목록](https://github.com/strapi/strapi/blob/v5.58.0/packages/core/content-manager/admin/src/pages/EditView/components/FormInputs/BlocksInput/DefaultBlocksStore.tsx)
- Markdown 형식의 글은 Strapi와 같은 CodeMirror 5 입력·markdown-it 미리보기를 사용한다.
- 본문 형식을 `blocks`, `markdown`, `legacy-mdx`, `legacy-html`로 구분한다. Blocks와 Markdown 사이의 자동 왕복 변환은 하지 않는다.
- 기존 본문은 원문을 보존한다. 무손실 변환이 검증되지 않은 본문은 기존 표시 방식을 유지하고, 본문 외 정보만 편집할 수 있게 한다.
- 편집·미리보기·공개 표시가 같은 본문 규칙을 사용하도록 하고, 목차와 기존 글 스타일을 유지한다.

**Supabase**

연결 설정부터 초기 SQL 적용까지 포함한다. 빈 DB에서도 재현 가능하도록 마이그레이션을 만들고, 기존 테이블을 보존하는 `cms_` 접두사를 사용한다.

- 글·영상·시즌·일정·카운트다운·쿠폰·미디어 정보에 더해 사이트 설정·페이지 문구·메뉴·홈 섹션·링크·분류를 저장한다.
- 본문과 반복되는 설정은 검증된 구조의 JSON을 사용할 수 있지만, 관리자에게 원시 JSON 편집을 요구하지 않는다.
- 영상 분류 등 운영 데이터는 TypeScript의 고정 목록 대신 DB 식별자와 타입이 명확한 조회 결과를 사용한다.
- DB 접근은 서버 전용으로 제한한다. 모든 변경 작업에서 운영자와 입력을 검증하고, 공개 조회는 공개 상태와 노출 설정을 함께 확인한다.
- NextAuth의 MongoDBAdapter와 Google provider를 제거한다. 자체 로그인과 JWT 세션의 발급·확인·로그아웃은 NextAuth에서 처리한다.
- 자체 로그인의 기본안은 단일 운영자의 ID·비밀번호를 사용하는 Credentials 방식이다. 비밀번호는 서버에서 검증하고 평문으로 저장하지 않는다. 공개 회원가입·회원 관리 기능은 추가하지 않는다.
- 운영자 권한은 NextAuth 세션의 신뢰할 수 있는 운영자 식별자로 확인한다. 페이지·Server Actions·업로드 경로에서 같은 검사를 사용하며 Google 이메일 일치 여부에 의존하지 않는다.

**Cloudflare R2**

- 직접 관리하는 이미지·파일은 R2에 저장하고 Supabase에는 주소·대체 설명·형식·크기 등을 기록한다.
- 운영자 확인 후 임시 업로드 주소를 발급해 브라우저에서 R2로 직접 전송한다. 업로드 완료를 서버에서 확인한 뒤 DB에 등록한다.
- 사용 중인 미디어 삭제를 차단한다. YouTube 원본 영상과 제공 썸네일은 외부 주소를 유지한다.
- 사이트 설정 저장은 공통 레이아웃·메타데이터·검색·사이트맵까지, 콘텐츠 저장은 관련 페이지까지 캐시를 갱신한다.

## 4. 공개 화면·디자인·이전

- 추천 영상은 `/videos`에 유지하고 클릭하면 YouTube로 이동한다. 영상 정보 불러오기와 수동 수정, 중복 ID 검사를 제공한다.
- 유튜버 목록·채널 상세·관련 데이터 변경 기능을 제거한다. 기존 영상 목록 주소는 `/videos`로, 확인 가능한 개별 영상 주소는 해당 YouTube 영상으로 이동한다.
- 시즌과 홈 카운트다운은 같은 시즌 날짜를 참조한다. 개별 이벤트만 자체 날짜를 가진다.
- 쿠폰 데이터는 CMS로 옮기고 기존 Nexon 쿠폰 사용 기능은 유지한다.
- 현재 공개 화면의 글꼴·색상·여백·반응형 배치·본문·상태 표현을 확인해 `DESIGN.md`를 작성한다. 관리자 화면에는 Strapi에서 재사용한 규칙과 필요한 조정 사유를 별도로 기록한다.
- 직접 만든 아이콘은 Lucide를 사용한다. 수정하지 않고 재사용한 Strapi 원본 아이콘만 예외로 유지한다.

이전은 최신 MongoDB 데이터와 현재 코드에 있는 운영 데이터를 대상으로 한다. 고정 데이터마다 **기존 위치 → DB 항목 → 관리자 입력 화면 → 공개 사용처** 대응표를 작성해 누락을 확인한다.

미디어 주소 변경, 본문·공개 상태·기존 글 주소 보존, 재실행 시 중복 방지를 검증한다. 원본은 검증 완료까지 보존하며 초기 데이터 입력을 다시 실행해도 이후 관리자 수정값을 덮어쓰지 않는다.

이전 검증이 끝나면 글 조회·저장·공개 전환·영상 처리에 남은 MongoDB 사용처를 모두 교체하고 연결 모듈·패키지·환경변수를 제거한다. 과거 Google 로그인 설정, `restore:posts` 명령과 복원 도구, MongoDB 전용 테스트와 CI 준비 단계도 제거하거나 새 저장 방식에 맞게 교체한다.

기존 복원 도구의 Windows 실행 문제를 별도로 수리하지 않는다. 새 이전 도구는 Windows와 Linux에서 시작·오류 처리를 확인하고, 연결 설정이나 입력 파일이 없을 때 성공으로 끝나지 않는지 검사한다.

구현 시작 시 수정 계획을 문서로 저장한다. 기존 계획의 Tiptap·TinyMCE 고도화·유튜버·배경음악·메뉴 및 푸터 편집 제외 항목을 이번 결정으로 대체한다.

## 5. 구현 순서와 완료 기준

**순서:** 기존 타입 오류 정리·검사 통과 → Strapi UI·편집기 호환성 검증 → 디자인·고정 데이터 대응표 → Supabase 초기 SQL·인증·R2 → 콘텐츠 관리 → 사이트 설정 → 전체 이전·검증 → MongoDB 의존성 정리 → Vercel Preview 검증.

**구현 시작 조건 — 충족:** 앞선 Windows 검사에서 발견한 `src/__tests__/actions/saveEdit.test.ts`와 `src/__tests__/actions/togglePublished.test.ts`의 인증 함수 모의 객체 타입 오류 14개를 해결하고 타입 검사와 관련 테스트를 통과한 뒤 CMS 구현을 시작했다.

**보안 테스트:** 모의 함수에 복제한 규칙만 검사하지 않고 실제 운영자 확인 함수와 새 조회 함수도 검사한다.

- Draft가 공개 본문·메타데이터·검색 결과·사이트맵에 나타나지 않는지 확인한다.
- 미로그인·운영자가 아닌 세션·만료된 세션으로 글 저장·공개 전환·영상 변경·업로드를 호출하면 거부되는지 확인한다. 관리자 화면의 접근 제한과 각 서버 변경 함수의 권한 검사를 함께 확인한다.

완료 조건:

- Next.js·React 19에서 이식한 편집기의 입력·선택·붙여넣기·한글 조합·실행 취소가 정상 동작한다.
- 표·이미지·YouTube·접기·Markdown의 저장 후 재열기와 공개 표시가 일치한다.
- 운영자만 변경·업로드할 수 있고 DB·R2 비밀정보가 브라우저에 노출되지 않는다.
- Draft 노출 방지와 권한 없는 변경·업로드 거부를 위 보안 테스트로 확인한다.
- Google 로그인 없이 NextAuth 자체 로그인·JWT 세션·로그아웃이 동작하고, 로그인 실패와 만료된 세션은 관리자 접근을 허용하지 않는다.
- 기존 글 주소·본문·미디어·공개 상태를 보존하고 이전 재실행 시 중복이 생기지 않는다.
- 새 이전 도구의 시작·오류 처리를 Windows와 Linux에서 확인한다.
- 이전 검증 후 MongoDB 사용 코드·연결 모듈·패키지·환경변수·과거 복원 도구가 남지 않고, 테스트와 CI도 새 저장 방식에 맞게 동작한다.
- 대응표의 모든 콘텐츠·운영 설정을 관리자에서 변경할 수 있다.
- 코드 변경이나 재배포 없이 메뉴·홈·문구·분류·검색 정보가 반영된다. 비운 값이나 숨긴 항목이 기본값으로 되살아나지 않는다.
- 시즌 날짜·쿠폰 만료·영상 이동·미디어 삭제 보호가 정상 동작한다.
- 배경음악과 유튜버 페이지가 제거되고 필요한 과거 주소 이동이 동작한다.
- 모바일·데스크톱과 밝은·어두운 화면을 확인하고 TypeScript 검사·관련 테스트·빌드를 통과한다.

### 실제 연결 확인 추가

- Windows·Codex에서 실제 R2의 임시 PNG 전송과 서명 주소를 통한 PUT 모두 HTTP 200. 크기·형식, 공개 주소의 원본 바이트 일치, 임시 파일 삭제까지 확인했다. 실제 콘텐츠의 업로드 완료 등록·사용 중 삭제 차단은 관리자 로그인과 DB 초기화 후 확인한다.
- 최초 localhost:3000 출처의 CORS 사전 요청은 HTTP 403이었다. 후속 요청은 HTTP 204와 해당 출처 허용을 확인했다. 이 작업에서 버킷 정책을 변경하지 않았으며 실제 관리자 업로드는 DB·로그인 설정 후 확인한다.
- Supabase 서비스 키 형식과 API 응답을 확인했으나 CMS 테이블 조회는 PGRST205다. 초기 SQL과 실제 콘텐츠 이전은 아직 적용하지 않았다.
- 후속 환경변수 점검에서 필수값 12개·비밀번호 해시 형식·API/DB 프로젝트 일치 확인. AUTH_SECRET을 포함한 앱 설정은 Next.js가 파일 내용대로 읽는 것도 확인했다. 비밀값은 출력하거나 Git에 추가하지 않았다.
- DATABASE_URL은 직접 접속 주소로 IPv6 DNS만 존재하고 현재 Windows에는 IPv6 기본 경로가 없어 getaddrinfo ENOENT로 접속 실패. DB 비밀번호는 아직 인증하지 못했다. Session pooler의 IPv4 접속 주소로 변경하고 SSL을 설정한 뒤 재검사한다.

### 두 연결 주소의 역할

- SUPABASE_URL: Supabase 클라이언트가 콘텐츠를 조회·저장하는 HTTPS Data API 주소. 서버 비밀키와 함께 사용한다.
- DATABASE_URL: cms:db:apply가 초기 테이블과 함수를 만드는 SQL을 실행하기 위한 PostgreSQL 접속 주소. DB 사용자·비밀번호를 사용한다.
- 두 주소는 같은 프로젝트를 가리키지만 접속 방식과 인증 정보가 다르다. 현재 환경의 PostgreSQL 접속은 Connect의 Session pooler 주소를 사용할 수 있다. [공식 연결 안내](https://supabase.com/docs/guides/database/connecting-to-postgres#pooler-session-mode)

### 남은 완료 기준

- `awaiting-external-evidence`: DATABASE_URL을 해당 프로젝트의 Session pooler 주소로 변경한 뒤 DB 인증·초기 SQL·실제 이전·관리자 변경 반영을 확인한다. 현재 값의 직접 접속은 이 호스트의 IPv6 경로 부재로 실패했다. 비밀값을 대화에 전달하지 않는다.
- `awaiting-external-evidence`: 실제 한국어 IME의 조합·선택·붙여넣기·실행 취소와 이미지/YouTube/Markdown의 실제 운영 파일 연결을 확인한다. 도구를 통한 한글 입력은 물리적 IME 검증을 대신하지 않는다.
- `awaiting-user-authority`: 실제 연결 검증 뒤 Vercel Preview 배포를 승인하면 Preview에서 변경 반영을 확인한다. 운영 배포·보호 브랜치 통합은 별도 승인 대상이다.

설정 순서는 로컬 `USER_TASKS.md`에 기록했다. 위 외부 검증을 완료하기 전에는 전체 운영 전환이 끝났다고 판단하지 않는다.
